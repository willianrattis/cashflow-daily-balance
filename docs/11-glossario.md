# Glossário

Este glossário reúne, em um só lugar, as siglas, os códigos e os termos técnicos usados na
documentação. Cada documento explica o termo no primeiro uso; aqui fica a definição completa e
o lugar onde o termo mais importa. Os nomes daqui são os oficiais: quando um conceito tem mais
de um nome possível, a documentação usa o que está nesta página.

Termos de uso geral não são expandidos nos documentos, mas também estão abaixo: API, HTTP,
HTTPS, JSON, SQL, URL, ID, UTC, PDF e BRL.

## Siglas

| Sigla (nome completo) | O que significa aqui | Onde importa |
|---|---|---|
| ACID (Atomicidade, Consistência, Isolamento e Durabilidade) | As quatro garantias de uma transação de banco: tudo é gravado ou nada é; as regras do banco continuam valendo; transações simultâneas não veem o trabalho incompleto umas das outras; o que foi confirmado sobrevive a uma queda. É o que permite gravar o lançamento e a mensagem a publicar juntos. | [ADR-008](adr/ADR-008-postgresql.md) |
| ACK (acknowledgement, confirmação de recebimento) | O consumidor avisa o broker que terminou de processar uma mensagem; só então o broker a apaga da fila. Aqui o Consolidado só envia o ACK depois que o próprio banco confirmou a gravação. O contrário é o NACK (negative acknowledgement): a mensagem volta para a fila. | [ADR-002](adr/ADR-002-integracao-assincrona.md), [ADR-004](adr/ADR-004-processamento-idempotente.md) |
| ADR (Architecture Decision Record, registro de decisão de arquitetura) | Documento curto que registra uma decisão: o problema, o que foi decidido, as alternativas descartadas e as consequências. | [docs/adr/](adr/README.md) |
| AGPL (Affero General Public License), BSD (Berkeley Software Distribution License), MIT (MIT License) e MPL (Mozilla Public License) | Licenças de software livre citadas na estimativa de custos. MIT e BSD são permissivas. MPL e AGPL obrigam a disponibilizar o código modificado; a AGPL também quando o software é usado pela rede. Nenhuma delas cobra licença. | [docs/08 §5](08-custos.md) |
| ALB (Application Load Balancer), RDS (Relational Database Service) e Amazon MQ (RabbitMQ gerenciado) | Serviços da AWS (Amazon Web Services) citados como equivalentes dos componentes da Arquitetura Alvo, caso o provedor de nuvem mude. GCP (Google Cloud Platform) é o provedor de nuvem do Google. | [docs/08 §1](08-custos.md) |
| AMQP (Advanced Message Queuing Protocol) | Protocolo que os serviços usam para falar com o RabbitMQ. AMQPS (AMQP sobre conexão criptografada) é a versão usada na Arquitetura Alvo. | [docs/03](03-contratos.md), [docs/06 §2](06-arquitetura-alvo.md) |
| APM (Application Performance Monitoring) | Produto pago que coleta métricas, logs e rastreamento de requisições num só lugar (por exemplo, Datadog ou New Relic). | [ADR-010](adr/ADR-010-observabilidade.md) |
| AZ (Availability Zone, zona de disponibilidade) | Data center isolado dentro de uma região de nuvem. Espalhar as cópias de um serviço por pelo menos duas zonas mantém o serviço no ar se uma delas cair. | [docs/06 §4](06-arquitetura-alvo.md) |
| C4 (modelo de diagramas de arquitetura em quatro níveis de zoom) | Forma padronizada de desenhar arquitetura, do mais amplo ao mais detalhado: contexto, containers, componentes e código. | [docs/diagrams/](diagrams/README.md) |
| C1 (nível 1 do modelo C4, contexto), C2 (nível 2, containers) e C3 (nível 3, componentes) | C1 mostra o sistema, as pessoas e os sistemas externos. C2 mostra cada aplicação, banco e broker que roda e como se comunicam. C3 não foi desenhado: os diagramas de sequência mostram os mecanismos internos. | [docs/diagrams/](diagrams/README.md) |
| CDC (Change Data Capture, captura de mudanças no banco) | Técnica que lê o log de transações do banco e transforma cada linha gravada em um evento, sem a aplicação publicar nada. Exemplo: o Debezium lendo o log do PostgreSQL e publicando no broker. Não usamos: exige uma ferramenta a mais para operar. | [ADR-003](adr/ADR-003-transactional-outbox.md) |
| CPU (Central Processing Unit, processador) | Usado nos sinais para criar mais cópias de um serviço e na estimativa de custos (vCPU é um processador virtual). | [docs/06 §6](06-arquitetura-alvo.md#6-escalabilidade), [docs/08](08-custos.md) |
| CQRS (Command Query Responsibility Segregation, separar escrita e leitura) | Padrão em que o modelo que recebe comandos (escrita) é diferente do modelo que responde consultas (leitura). A separação entre Lançamentos (escrita) e Consolidado (leitura, com banco próprio) segue essa ideia, sem nenhum framework de CQRS. | [ADR-001](adr/ADR-001-estilo-arquitetural.md), [ADR-005](adr/ADR-005-eventual-consistency.md) |
| CU (capacity unit, unidade de capacidade) | A unidade em que a Azure cobra o volume que o Application Gateway processa. | [docs/08 §2](08-custos.md) |
| CSP (Cloud Solution Provider) e EA (Enterprise Agreement) | Formas de contrato corporativo com a Microsoft que dão desconto sobre o preço de tabela. Não foram estimadas. | [docs/08 §1](08-custos.md) |
| DB (database, banco de dados) | Aparece nos nomes `Launch DB` (banco de Lançamentos) e `Consolidation DB` (banco do Consolidado). | [docs/04](04-schema-logico.md) |
| DLQ (Dead Letter Queue, fila das mensagens que não puderam ser processadas) | Fila para onde vão as mensagens que o Consolidado não conseguiu aplicar: evento inválido (na hora) ou erro inesperado (depois de três tentativas). Uma falha temporária de infraestrutura nunca manda mensagem para cá. Ter qualquer mensagem na DLQ gera alerta. | [ADR-002](adr/ADR-002-integracao-assincrona.md), [docs/07 §4](07-runbooks.md) |
| DoS (Denial of Service, negação de serviço) | Ataque que tenta derrubar um serviço com excesso de requisições. Contra quem tem token, cada serviço limita as requisições por chamador; contra quem não tem, a proteção é papel do gateway com WAF (Web Application Firewall), na Arquitetura Alvo. | [docs/05 §1](05-aspectos-transversais.md#1-segurança-e-modelo-de-ameaças), [ADR-012](adr/ADR-012-borda-gateway-waf-cache.md) |
| DR (Disaster Recovery, recuperação de desastre) | Plano para voltar a operar se uma região de nuvem inteira cair. Não faz parte desta entrega. | [docs/06 §4](06-arquitetura-alvo.md) |
| DSL (Domain-Specific Language, linguagem própria de uma ferramenta) | Aqui, a linguagem do Structurizr em que o modelo C4 está escrito (`workspace.dsl`). | [docs/diagrams/](diagrams/README.md) |
| ELK (Elasticsearch, Logstash e Kibana) | Conjunto de ferramentas para centralizar e pesquisar logs. Descartado por ser pesado demais para rodar localmente. | [ADR-010](adr/ADR-010-observabilidade.md) |
| ES256 (assinatura digital com curva elíptica e SHA-256) | Forma de assinar tokens com um par de chaves: o provedor de identidade assina com a chave privada e os serviços validam com a chave pública. O ADR-007 o cita como alternativa ao RS256 (RSA com SHA-256, explicado abaixo); a Arquitetura Alvo (`docs/06-arquitetura-alvo.md` §8) usa RS256. | [ADR-007](adr/ADR-007-identity-provider-externo.md) |
| ESB (Enterprise Service Bus, barramento de serviços corporativo) | Peça central que roteia, transforma e orquestra mensagens entre sistemas. Descartado: dois serviços não precisam de um intermediário central. | [ADR-001](adr/ADR-001-estilo-arquitetural.md) |
| FK (Foreign Key, chave estrangeira) | Restrição do banco que obriga uma coluna a apontar para uma linha que existe em outra tabela. O schema desta entrega não tem nenhuma. | [docs/04](04-schema-logico.md) |
| GA (General Availability, versão estável) | Versão de um produto liberada para uso em produção, não mais prévia. | [ADR-009](adr/ADR-009-dotnet-minimal-apis.md) |
| HA (High Availability, alta disponibilidade) | Manter o serviço no ar quando uma peça falha, com cópias redundantes e troca automática para a cópia saudável (failover). | [docs/06 §4](06-arquitetura-alvo.md) |
| HS256 (HMAC com SHA-256, assinatura com chave simétrica) | Forma de assinar tokens em que quem assina e quem valida usam a mesma chave secreta. Usada só no ambiente local: qualquer um que conheça a chave pode criar tokens válidos. | [ADR-007](adr/ADR-007-identity-provider-externo.md) |
| IdP (Identity Provider, provedor de identidade) | Sistema externo que autentica pessoas e sistemas e emite os tokens de acesso (por exemplo, Microsoft Entra ID, Auth0 ou Okta). Os serviços só validam esses tokens. | [ADR-007](adr/ADR-007-identity-provider-externo.md) |
| IOPS (operações de entrada e saída por segundo) | Medida de capacidade do disco de um banco de dados. | [docs/06 §6](06-arquitetura-alvo.md) |
| JVM (Java Virtual Machine) | O ambiente que executa programas Java. Citada ao comparar o tempo de partida e o consumo de memória das plataformas. | [ADR-009](adr/ADR-009-dotnet-minimal-apis.md) |
| JWKS (JSON Web Key Set, conjunto de chaves públicas) | Endereço onde o provedor de identidade publica as chaves públicas com que os serviços validam a assinatura dos tokens. Com ele, nenhum serviço precisa guardar um segredo de assinatura. | [ADR-007](adr/ADR-007-identity-provider-externo.md), [docs/06 §8](06-arquitetura-alvo.md) |
| JWT (JSON Web Token) | Token de acesso assinado que diz quem é o chamador (campo `sub`), para qual API o token vale (`aud`), até quando vale (`exp`) e o que o chamador pode fazer (`scope`). Toda requisição de negócio precisa de um, no cabeçalho `Authorization: Bearer <token>`. | [ADR-007](adr/ADR-007-identity-provider-externo.md), [docs/03](03-contratos.md) |
| KB (kilobyte) e GB (gigabyte) | Unidades de tamanho. O limite do corpo de uma requisição é 64 KB (65.536 bytes). | [docs/05 §1](05-aspectos-transversais.md) |
| KMS (Key Management Service, cofre de chaves gerenciado) | Serviço de nuvem que guarda chaves e segredos fora do código e da configuração. Previsto na Arquitetura Alvo. | [docs/06 §8](06-arquitetura-alvo.md) |
| L7 (camada 7, a camada de aplicação) | A sétima camada do modelo de rede OSI (Open Systems Interconnection), que divide a comunicação em sete camadas. Rotear pela camada de aplicação é escolher o destino de cada requisição olhando o caminho ou os cabeçalhos HTTP, e não só o endereço de rede. É o que o API Gateway faz na Arquitetura Alvo. | [ADR-012](adr/ADR-012-borda-gateway-waf-cache.md) |
| LINQ (Language Integrated Query) | Consultas escritas em C# que o Entity Framework traduz para SQL. | [ADR-009](adr/ADR-009-dotnet-minimal-apis.md) |
| LTS (Long-Term Support) e STS (Standard-Term Support) | Tipos de versão do .NET. A LTS recebe correções por três anos; a STS, por menos tempo. O .NET 10 é LTS. | [ADR-009](adr/ADR-009-dotnet-minimal-apis.md) |
| MAU (Monthly Active Users, usuários ativos por mês) | Unidade de cobrança comum dos provedores de identidade. | [docs/08 §2](08-custos.md) |
| mTLS (TLS mútuo) | Conexão criptografada em que os dois lados apresentam certificado, e não só o servidor. Evolução opcional da Arquitetura Alvo. | [docs/06 §8](06-arquitetura-alvo.md) |
| OAuth 2.0 (Open Authorization) | Padrão de autorização em que um provedor emite tokens de acesso e as APIs (os "resource servers") os validam. | [ADR-007](adr/ADR-007-identity-provider-externo.md) |
| OIDC (OpenID Connect) | Camada de login sobre o OAuth 2.0: padroniza como o provedor de identidade autentica a pessoa e publica suas chaves. | [ADR-007](adr/ADR-007-identity-provider-externo.md), [docs/06 §8](06-arquitetura-alvo.md) |
| ORM (Object-Relational Mapper) | Biblioteca que converte objetos do código em linhas de tabela e vice-versa. Aqui, o Entity Framework Core. | [ADR-009](adr/ADR-009-dotnet-minimal-apis.md) |
| OSS (Open Source Software, software de código aberto) | Toda a pilha local é OSS: nada a pagar para rodar o projeto. | [docs/08 §5](08-custos.md) |
| OTLP (OpenTelemetry Protocol) | Protocolo padrão para enviar métricas, logs e rastreamento a um coletor. Previsto na Arquitetura Alvo. | [docs/06 §2](06-arquitetura-alvo.md) |
| PK (Primary Key, chave primária) | Coluna (ou conjunto de colunas) que identifica cada linha de uma tabela e não pode se repetir. | [docs/04](04-schema-logico.md) |
| POS (Point of Sale, ponto de venda) | A maquininha ou o sistema de caixa da loja. Citado como um sistema que, no futuro, poderia enviar lançamentos automaticamente. | [ADR-004](adr/ADR-004-processamento-idempotente.md) |
| PR (Pull Request) | Pedido de alteração no GitHub. A integração contínua roda os testes a cada push e a cada PR. | [README](../README.md) |
| REST (Representational State Transfer) | Estilo de API sobre HTTP, com recursos (`/launches`) e verbos (`GET`, `POST`). | [docs/03](03-contratos.md) |
| RLS (Row-Level Security, segurança por linha) | Recurso do PostgreSQL que filtra, dentro do próprio banco, as linhas que cada conexão pode ver. Citado para um futuro com vários comerciantes. | [ADR-006](adr/ADR-006-isolamento-de-dados.md) |
| RPO (Recovery Point Objective, perda máxima aceitável) | Quanto dado se aceita perder numa falha, medido em tempo. RPO 0 para Lançamentos significa que nenhum lançamento confirmado ao cliente pode se perder. | [docs/06 §5](06-arquitetura-alvo.md) |
| RS256 (RSA com SHA-256, assinatura com par de chaves) | Como o ES256: o provedor de identidade assina com a chave privada e os serviços validam com a chave pública, obtida pelo JWKS. É o padrão da Arquitetura Alvo. | [ADR-007](adr/ADR-007-identity-provider-externo.md) |
| RTO (Recovery Time Objective, tempo máximo para voltar) | Quanto tempo o serviço pode ficar fora depois de uma falha: até 15 minutos para Lançamentos e até 60 minutos para o Consolidado. | [docs/06 §5](06-arquitetura-alvo.md) |
| SaaS (Software as a Service) | Software contratado como serviço na internet, pago por uso, em vez de instalado e operado pela equipe. | [ADR-010](adr/ADR-010-observabilidade.md) |
| SDK (Software Development Kit) | Aqui, o compilador e as ferramentas do .NET. O arquivo `global.json` fixa a versão. | [ADR-009](adr/ADR-009-dotnet-minimal-apis.md) |
| SIEM (Security Information and Event Management) e SSO (Single Sign-On) | Sistemas corporativos de análise de eventos de segurança e de login único. Integrar com eles não foi estimado. | [docs/08 §1](08-custos.md) |
| SKU (Stock Keeping Unit) | Nome do plano ou tamanho de um serviço de nuvem (por exemplo, `WAF_v2`). | [docs/08 §2](08-custos.md) |
| SLA (Service Level Agreement, acordo de nível de serviço) | Compromisso contratual com o cliente, com penalidade se não for cumprido. Não existe nesta entrega. | [docs/01](01-requisitos-e-assumptions.md) |
| SLO (Service Level Objective, meta de nível de serviço) | Meta interna, medida e acompanhada pela equipe. Exemplos: 99,9% de disponibilidade por mês; p95 do registro de lançamento até 300 ms. | [docs/01](01-requisitos-e-assumptions.md), [docs/05 §3](05-aspectos-transversais.md) |
| SOA (Service-Oriented Architecture, arquitetura orientada a serviços) | Estilo em que sistemas expõem serviços e conversam, em geral, por um barramento central. | [ADR-001](adr/ADR-001-estilo-arquitetural.md) |
| SVG (Scalable Vector Graphics) | Formato de imagem dos diagramas gerados a partir do modelo C4. | [docs/diagrams/](diagrams/README.md) |
| TCP (Transmission Control Protocol) | Protocolo de rede sobre o qual rodam as conexões com o banco e o broker. | [docs/diagrams/](diagrams/README.md) |
| TLS (Transport Layer Security) | Criptografia da conexão (o "S" do HTTPS). No ambiente local, o tráfego interno roda sem TLS; na Arquitetura Alvo, o gateway encerra o HTTPS e as conexões com banco e broker usam TLS. | [ADR-012](adr/ADR-012-borda-gateway-waf-cache.md), [docs/06 §8](06-arquitetura-alvo.md) |
| TTL (Time To Live, tempo de vida) | Tempo depois do qual algo expira. Aparece em dois lugares: o tempo que uma mensagem fica numa fila de espera antes de voltar para a fila principal (5 s, 30 s e 120 s) e a validade de um token de acesso (60 minutos nos tokens de desenvolvimento). | [ADR-011](adr/ADR-011-topologia-de-processos.md), [ADR-007](adr/ADR-007-identity-provider-externo.md) |
| UI (User Interface, interface gráfica) | Telas para pessoas. Esta entrega não tem interface gráfica própria; o Swagger UI só documenta a API. | [docs/01](01-requisitos-e-assumptions.md) |
| USD (dólar americano) | Moeda das estimativas de custo; nos documentos aparece com o símbolo do dólar (US$). | [docs/08](08-custos.md) |
| UUID (Universally Unique Identifier) | Identificador de 128 bits gerado sem coordenação central. Usado em `launchId` e `eventId`. | [docs/04](04-schema-logico.md) |
| VM (Virtual Machine, máquina virtual) e VPN (Virtual Private Network, rede privada virtual) | Termos de infraestrutura da Arquitetura Alvo: as ferramentas de operação só seriam acessíveis por rede privada. | [docs/06 §8](06-arquitetura-alvo.md) |

| WAF (Web Application Firewall) | Filtro na entrada do sistema que bloqueia ataques conhecidos (por exemplo, injeção de SQL) antes que a requisição chegue aos serviços. Previsto na Arquitetura Alvo. | [ADR-012](adr/ADR-012-borda-gateway-waf-cache.md) |

## Termos técnicos

| Termo | O que significa aqui | Onde importa |
|---|---|---|
| Append-only (só inclusão) | A tabela `launches` aceita apenas novas linhas. Um trigger do banco rejeita qualquer `UPDATE` ou `DELETE`. Para corrigir um lançamento errado, registra-se um novo lançamento de natureza oposta. | [ADR-008](adr/ADR-008-postgresql.md), [docs/04](04-schema-logico.md) |
| At-least-once, at-most-once e exactly-once | Garantias de entrega de mensagens. "Pelo menos uma vez" (at-least-once): nada se perde, mas a mesma mensagem pode chegar duas vezes. "No máximo uma vez" (at-most-once): nunca duplica, mas pode perder. "Exatamente uma vez" (exactly-once): nem perde nem duplica — o broker não consegue garantir isso sozinho até o banco de quem consome. Usamos "pelo menos uma vez" e descartamos as cópias repetidas no consumidor. | [ADR-002](adr/ADR-002-integracao-assincrona.md), [ADR-004](adr/ADR-004-processamento-idempotente.md) |
| Audience (`aud`) | Campo do token que diz para qual API ele vale. As duas APIs desta entrega aceitam o mesmo valor, `cashflow-api`; na Arquitetura Alvo, cada API teria o seu. | [docs/03](03-contratos.md#autenticação-e-cabeçalhos), [ADR-007](adr/ADR-007-identity-provider-externo.md) |
| Autoscaling (criação automática de cópias) | O provedor cria ou remove cópias de um serviço conforme um sinal, como requisições por segundo ou mensagens na fila. | [docs/06 §6](06-arquitetura-alvo.md#6-escalabilidade) |
| Backfill (cópia do histórico) | Copiar o histórico de um sistema legado para o sistema novo. Aqui, um job de importação, fora da API pública, que grava cada lançamento com a data original. | [docs/06 §10](06-arquitetura-alvo.md#10-arquitetura-de-transição-df-01) |
